# 补货分析台 · 库存情景模拟

面向补货计划员的库存补货分析与情景模拟应用。输入销量预测、供应周期、最小批量与安全库存，
输出库存曲线、缺口区间与补货单；支持缺货、退货、替代品与供应中断。**模拟结果永远不会覆盖正式计划**，
参数与数据版本可复现，方案确认后生成差异与审批记录。

## 快速开始

```bash
npm start          # 启动服务，默认 http://localhost:4173
npm test           # 引擎 + API 测试（32 项）
```

零外部依赖：Node 内置 `http` + `node:sqlite`，前端为原生 ES Module，无需构建。
要求 Node ≥ 22.5（使用 `node:sqlite`）。

首次启动自动写入演示数据（5 个 SKU、42 天销量预测、5 个预置情景与 1 份正式计划），
数据库文件位于 `data/inventory.db`。删除 `data/` 即可重置。

环境变量：`PORT`（端口）、`DB_PATH`（数据库路径）。

## 核心概念

| 概念 | 说明 |
|---|---|
| 数据版本 | 销量预测 / 期初库存 / 在途订单的快照，按内容哈希去重 |
| 情景（Scenario） | 一组参数 + 绑定一个数据版本；草稿 → 已模拟 → 审批中 → 已确认 |
| 正式计划（Plan） | 由**批准**的方案生成的版本化补货单，只追加版本，历史版本标记为「已替代」 |
| 审批（Approval） | 记录提交、差异、审批人与意见；批准时才生成计划 |

状态流转：

```
草稿 ──模拟──▶ 已模拟 ──提交审批──▶ 审批中 ──批准──▶ 已确认（并生成正式计划 vN+1）
                     ▲                 │
                     └──────驳回───────┘
```

## 可复现性设计

- 模拟引擎为纯函数：`simulate(dataset, params)`，无隐藏状态、无随机数、无当前时间参与计算。
- 参数在校验阶段被**完全规范化**（补齐默认值、按 SKU 展开安全库存），规范化结果参与哈希。
- 哈希使用键排序后的规范 JSON：
  - `inputHash` = 引擎版本 + 数据哈希 + 规范化参数
  - `resultHash` = 完整模拟输出（含逐日曲线）
- 每次模拟把 `{参数, 完整数据集, 数据版本元信息}` 存为快照；「校验可复现」会用快照重算并比对两个哈希。
- 批准前再次校验快照哈希，并检查正式计划基线是否仍与申请时一致——基线变化则拒绝批准，避免差异失真。

## 模拟规则

逐日推进，每个 SKU 独立：

1. **到货**：在途订单按承诺日到货；可对单个 PO 执行延迟或取消；供应中断期间（`delay` 模式）到货统一推后 N 天，
   `halt` 模式则推到中断结束次日。迟到天数按「实际到货 − 原承诺日」计入统计。
2. **需求**：`销量预测 × 需求系数`，预测用尽后沿用均值。
3. **满足**：先消耗本 SKU 在库；不足时（若启用替代且配置了替代品）按 `maxShare`（每单最大替代比例）
   与替代品库存上限补足，并记录替代耗用量（`ratio` 换算）。
4. **退货**：按已满足主商品销量的 `ratePercent` 生成退货，滞后 `lagDays` 天后回流为在库。
5. **补货**：每 `reviewPeriodDays` 天复核一次，`再订货点 = 供应周期需求 + 安全库存`；
   若 `在库 + 在途 ≤ 再订货点`，补到 `再订货点 + 复核周期需求`，向上取整到批量倍数，且不低于最小批量。
6. **缺口区间**：连续未满足需求的日期合并为区间，区分「缺货」与「替代品补足」；低于安全库存的区间单独统计。

## 页面

- **情景工作台**：参数表单（含逐 SKU 安全库存、退货、替代、供应中断、在途订单调整）、库存曲线、
  缺口区间、在途与到货（迟到 / 取消）、逐日数据表。
- **方案比较**：基线（正式计划或任一已模拟方案）与候选方案的指标对比、分 SKU 对比、
  在库曲线叠加、补货单差异（新增 / 调整 / 移除，可展开）。
- **审批与记录**：待审批与已处理审批、差异摘要与哈希、确认过程时间线、操作审计日志。
- **正式计划**：版本列表、计划明细、哈希与 JSON 下载。

## API 摘要

```
GET    /api/meta
GET    /api/datasets                    POST /api/datasets
GET    /api/scenarios                   POST /api/scenarios
GET    /api/scenarios/:id               PATCH /api/scenarios/:id      DELETE /api/scenarios/:id
POST   /api/scenarios/:id/simulate
POST   /api/scenarios/:id/verify        # 快照重算并比对哈希
GET    /api/scenarios/:id/compare[?against=<scenarioId>]
POST   /api/scenarios/:id/request-approval
GET    /api/plans                       GET  /api/plans/:id
GET    /api/approvals                   GET  /api/approvals/:id
POST   /api/approvals/:id/decide        # { decision: approve|reject, decidedBy, decisionNote }
GET    /api/audit?limit=60
```

请求头 `x-actor` 用于记录操作人（前端默认取「操作人」输入框）。

## 测试覆盖

- 引擎：哈希稳定性与敏感性、参数键序无关、库存守恒、MOQ/批量倍数、替代与退货、供应中断两种模式、
  取消与延迟在途、取消后补单恢复、缺口区间一致性、参数校验。
- API：模拟不覆盖正式计划、审批通过生成新版本并替代旧版本、驳回不生成计划、
  审批中/已确认方案锁定、审批基线变化拒绝批准、快照复现、数据版本去重、比较接口、审计日志。
